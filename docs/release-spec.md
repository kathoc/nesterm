# Public terminal release

## Scope

Publish kathoc/nesterm as a CLI-only public GitHub repository, with an English user-facing README and a one-line installer for macOS and Linux. Never include browser interfaces, browser tooling, ROMs, personal work notes, credentials or recordings in future Git commits or release archives.

## CLI-only boundary (2026-09-28)

The initial public revision included browser files because the Git source boundary was broader than the terminal package allowlist. The owner has now explicitly prohibited all future browser-interface publication to this repository.

Plan, in priority order:

1. Remove browser files from the Git index only; preserve local files and existing deployment. High benefit, low cost; adopted.
2. Remove browser documentation, npm commands, dependency and CI job. High benefit, low cost; adopted.
3. Ignore local browser sources, controller vendors, tests and tooling. High benefit, low cost; adopted.
4. Check an explicit tracked-file allowlist in local hooks and CI. High benefit, moderate cost; adopted. New CLI files require deliberate allowlist review.
5. Verify tests and packaging from an isolated index export without local browser files. High benefit, low cost; adopted.
6. Rewrite existing public history and tags. Disruptive and not authorized; not adopted. Older commits retain their historical contents.

Completion: current public main contains only CLI implementation and its supporting documentation/tooling; a forced addition of a browser path is rejected by the guard; clean-export CLI tests and archive smoke checks pass. No changes to the separate reference project's repository or the deployed site. Record the final verification below.

## Packaging decision

|Approach|Benefit|Cost|Decision|
|---|---|---|---|
|Global npm install from GitHub|Very little packaging code|Requires Node/npm/Git and potentially global write permissions|Offer npm tarball installation as an alternative|
|User-local installer + bundled npm archive|One command, no sudo or npm required|Needs a small tested shell installer|Primary path|
|OS-specific executable bundles|No runtime download|Four build targets and native packaging overhead|Defer|
|Homebrew tap|Familiar on macOS|Requires Homebrew and a second repository|Defer|
|Clone and run from source|Transparent development workflow|Too many steps for players|Document for development|

The release archive is generated by npm pack. It contains the CLI, renderer, core dependency, English README and all necessary licenses. Use a `files` allowlist and `bundleDependencies` for @nesjs/core. Publish SHA256SUMS beside the archive. The primary command downloads install.sh from this repository's main branch, pipes it to sh, then exports `$HOME/.local/bin` on PATH for the current shell.

## Installer contract

POSIX shell; Linux/macOS on x86_64 and arm64/aarch64. Default prefix is `$HOME/.local`, overridable with NESTERM_PREFIX (absolute, non-root path). Install no files outside that prefix. Reuse Node.js >=20 if present, otherwise download a private Node.js v24.21.0 runtime from nodejs.org and validate its official SHA256SUMS. Archive name is nesterm-0.1.0.tgz, release base URL is https://github.com/kathoc/nesterm/releases/download/v0.1.0. NESTERM_VERSION may select another version. Download with curl (or wget), finite connection/transfer limits, verify checksums before extracting, stage installation in a unique temporary directory, and avoid deleting or replacing unrelated files. Use a marker for managed installs. Rerunning the installer must be safe. Support spaces in prefix. Do not edit shell startup files; report the exact PATH command if needed. The launcher is `$prefix/bin/nesterm`. Explicitly document the fallback absolute launcher path.

Installer-only overrides for deterministic tests: NESTERM_RELEASE_BASE_URL (fixture HTTP server), NESTERM_NODE_BASE_URL (fixture server), NESTERM_FORCE_NODE_DOWNLOAD=1. Test cleanup may remove only known test temporary directories.

## Work split and acceptance

1. Parent: package metadata, dependency bundling, README, Git initialization, publication, final review and clean installation from the public release.
2. Installer implementation: install.sh and its bounded tests; no edits outside assigned files.
3. CI/public-source preparation: macOS/Linux workflow, ROM-free integration test and portable development scripts; no edits to installer, package.json or README.

Acceptance: existing tests pass; bundled release works with no npm install; installer succeeds in a temporary prefix including a path with spaces, verifies hashes, rejects bad archives, is repeatable and does not need sudo; GitHub Actions passes on Linux and macOS; public repository and release are readable without authentication; installation using the published artifacts runs nesterm --help and an emulator smoke test. Preserve local SMB3 integration but make it opt-in via NESTERM_ROM for other users and CI.
